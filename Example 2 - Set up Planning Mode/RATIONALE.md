# Planning Mode rationale

Asking for a plan before action pays off: a short written plan states the
goal, the steps, how success is checked, and how to undo mistakes. The
assistant drafts it, you correct it, and only then does the work start.

- One coordinator breaks the job into short tasks, then integrates results.
- Every plan states acceptance criteria, verification checks, and rollback.
- Questions reshape the plan; answers are recorded, never guessed.

## The plan format (adapt freely)

1. Direct response — what was heard.
2. Executive summary — goal and approach in a few sentences.
3. Acceptance criteria — numbered and testable.
4. Plan table — step, plain-words summary, judgment needed, order.
5. Verification — how to check each criterion.
6. Rollback — how to undo safely.
7. Questions — open items, or "none".

## The template

`template.md` is the format the assistant fills in when producing plans,
so output looks the same every time. You can customize its sections, but
you don't need to edit it to benefit from planning — just ask for a plan.
Template syntax reference: https://github.com/obsidianmd/knap
